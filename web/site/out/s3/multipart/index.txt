<h2>Multipart upload</h2>
<p>For objects bigger than ~100 MiB or unreliable network paths. Split the data into 5 MiB+ parts, upload each (in parallel if you want), then complete.</p>

<h3>Limits</h3>
<ul>
  <li>Up to <strong>10,000 parts</strong> per upload.</li>
  <li>Total size up to <strong>5 GiB</strong> per multipart upload.</li>
  <li>Minimum part size: <strong>5 MiB</strong> (except the last).</li>
  <li>Abandoned uploads are auto-cleaned after <strong>24 hours</strong>.</li>
</ul>

<h3>aws-cli (handles parts automatically)</h3>
<pre><code class="lang-bash">aws --endpoint-url http://localhost:9000 \
  s3 cp ./big-video.mp4 s3://media/big-video.mp4 \
  --expected-size 4294967296</code></pre>
<p>Above 8 MiB, aws-cli automatically switches to multipart. For really big files, tune the chunk size:</p>
<pre><code class="lang-bash">aws configure set default.s3.multipart_chunksize 64MB
aws configure set default.s3.multipart_threshold 64MB
aws configure set default.s3.max_concurrent_requests 16</code></pre>

<h3>boto3 high-level</h3>
<pre><code class="lang-python"><span class="kw">from</span> boto3.s3.transfer <span class="kw">import</span> TransferConfig

cfg = TransferConfig(
    multipart_threshold=<span class="num">64</span>*<span class="num">1024</span>*<span class="num">1024</span>,
    multipart_chunksize=<span class="num">16</span>*<span class="num">1024</span>*<span class="num">1024</span>,
    max_concurrency=<span class="num">8</span>
)

s3.upload_file(<span class="str">"big-video.mp4"</span>, <span class="str">"media"</span>, <span class="str">"big-video.mp4"</span>, Config=cfg)</code></pre>

<h3>Raw multipart lifecycle</h3>

<h4>1. Initiate</h4>
<pre><code class="lang-bash">curl -X POST <span class="str">"http://localhost:9000/media/big-video.mp4?uploads"</span> \
  --aws-sigv4 <span class="str">"aws:amz:us-east-1:s3"</span> \
  --user <span class="str">"minioadmin:minioadmin"</span></code></pre>
<p>Server returns the upload id:</p>
<pre><code class="lang-xml"><span class="kw">&lt;InitiateMultipartUploadResult&gt;</span>
  <span class="kw">&lt;Bucket&gt;</span>media<span class="kw">&lt;/Bucket&gt;</span>
  <span class="kw">&lt;Key&gt;</span>big-video.mp4<span class="kw">&lt;/Key&gt;</span>
  <span class="kw">&lt;UploadId&gt;</span>up_a3f8c01...<span class="kw">&lt;/UploadId&gt;</span>
<span class="kw">&lt;/InitiateMultipartUploadResult&gt;</span></code></pre>

<h4>2. Upload each part</h4>
<pre><code class="lang-bash">curl -X PUT --data-binary @part1 \
  <span class="str">"http://localhost:9000/media/big-video.mp4?partNumber=1&amp;uploadId=up_a3f8c01..."</span> \
  --aws-sigv4 <span class="str">"aws:amz:us-east-1:s3"</span> \
  --user <span class="str">"minioadmin:minioadmin"</span>
<span class="co"># Server returns ETag in response header — capture it for the complete step</span></code></pre>

<h4>3. Complete</h4>
<pre><code class="lang-bash">curl -X POST <span class="str">"http://localhost:9000/media/big-video.mp4?uploadId=up_a3f8c01..."</span> \
  --aws-sigv4 <span class="str">"aws:amz:us-east-1:s3"</span> \
  --user <span class="str">"minioadmin:minioadmin"</span> \
  -d <span class="str">'&lt;CompleteMultipartUpload&gt;
    &lt;Part&gt;&lt;PartNumber&gt;1&lt;/PartNumber&gt;&lt;ETag&gt;"abc1"&lt;/ETag&gt;&lt;/Part&gt;
    &lt;Part&gt;&lt;PartNumber&gt;2&lt;/PartNumber&gt;&lt;ETag&gt;"abc2"&lt;/ETag&gt;&lt;/Part&gt;
    &lt;Part&gt;&lt;PartNumber&gt;3&lt;/PartNumber&gt;&lt;ETag&gt;"abc3"&lt;/ETag&gt;&lt;/Part&gt;
&lt;/CompleteMultipartUpload&gt;'</span></code></pre>

<h4>4. Or abort</h4>
<pre><code class="lang-bash">curl -X DELETE <span class="str">"http://localhost:9000/media/big-video.mp4?uploadId=up_a3f8c01..."</span> \
  --aws-sigv4 <span class="str">"aws:amz:us-east-1:s3"</span> \
  --user <span class="str">"minioadmin:minioadmin"</span></code></pre>

<h3>Parallel parts in Python</h3>
<pre><code class="lang-python"><span class="kw">from</span> concurrent.futures <span class="kw">import</span> ThreadPoolExecutor

resp = s3.create_multipart_upload(Bucket=<span class="str">"media"</span>, Key=<span class="str">"video.mp4"</span>)
upload_id = resp[<span class="str">"UploadId"</span>]

<span class="kw">def</span> <span class="fn">upload_part</span>(part_number, body):
    r = s3.upload_part(
        Bucket=<span class="str">"media"</span>, Key=<span class="str">"video.mp4"</span>,
        UploadId=upload_id, PartNumber=part_number, Body=body
    )
    <span class="kw">return</span> {<span class="str">"PartNumber"</span>: part_number, <span class="str">"ETag"</span>: r[<span class="str">"ETag"</span>]}

<span class="kw">with</span> open(<span class="str">"video.mp4"</span>, <span class="str">"rb"</span>) <span class="kw">as</span> f:
    parts_data = [(i+<span class="num">1</span>, f.read(<span class="num">16</span>*<span class="num">1024</span>*<span class="num">1024</span>)) <span class="kw">for</span> i <span class="kw">in</span> range(<span class="num">10</span>)]

<span class="kw">with</span> ThreadPoolExecutor(max_workers=<span class="num">8</span>) <span class="kw">as</span> ex:
    parts = list(ex.map(<span class="kw">lambda</span> p: upload_part(*p), parts_data))

s3.complete_multipart_upload(
    Bucket=<span class="str">"media"</span>, Key=<span class="str">"video.mp4"</span>,
    UploadId=upload_id, MultipartUpload={<span class="str">"Parts"</span>: parts}
)</code></pre>

<h3>List in-progress uploads</h3>
<pre><code class="lang-bash">aws --endpoint-url http://localhost:9000 s3api list-multipart-uploads --bucket media</code></pre>

<div class="docs-callout"><strong>Auto-cleanup:</strong> abandoned multipart uploads (started but never completed or aborted) are removed 24 hours later. No manual janitor needed.</div>
