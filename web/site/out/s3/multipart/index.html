S3 · API

Multipart upload

For objects bigger than ~100 MiB or unreliable network paths. Split the data into 5 MiB+ parts, upload each (in parallel if you want), then complete.

Limits

  • Up to 10,000 parts per upload.
  • Total size up to 5 GiB per multipart upload.
  • Minimum part size: 5 MiB (except the last).
  • Abandoned uploads are auto-cleaned after 24 hours.

aws-cli (handles parts automatically)

aws --endpoint-url http://localhost:9000 \
  s3 cp ./big-video.mp4 s3://media/big-video.mp4 \
  --expected-size 4294967296

Above 8 MiB, aws-cli automatically switches to multipart. For really big files, tune the chunk size:

aws configure set default.s3.multipart_chunksize 64MB
aws configure set default.s3.multipart_threshold 64MB
aws configure set default.s3.max_concurrent_requests 16

boto3 high-level

from boto3.s3.transfer import TransferConfig

cfg = TransferConfig(
    multipart_threshold=64*1024*1024,
    multipart_chunksize=16*1024*1024,
    max_concurrency=8
)

s3.upload_file("big-video.mp4", "media", "big-video.mp4", Config=cfg)

Raw multipart lifecycle

1. Initiate

curl -X POST "http://localhost:9000/media/big-video.mp4?uploads" \
  --aws-sigv4 "aws:amz:us-east-1:s3" \
  --user "minioadmin:minioadmin"

Server returns the upload id:

<InitiateMultipartUploadResult>
  <Bucket>media</Bucket>
  <Key>big-video.mp4</Key>
  <UploadId>up_a3f8c01...</UploadId>
</InitiateMultipartUploadResult>

2. Upload each part

curl -X PUT --data-binary @part1 \
  "http://localhost:9000/media/big-video.mp4?partNumber=1&uploadId=up_a3f8c01..." \
  --aws-sigv4 "aws:amz:us-east-1:s3" \
  --user "minioadmin:minioadmin"
# Server returns ETag in response header — capture it for the complete step

3. Complete

curl -X POST "http://localhost:9000/media/big-video.mp4?uploadId=up_a3f8c01..." \
  --aws-sigv4 "aws:amz:us-east-1:s3" \
  --user "minioadmin:minioadmin" \
  -d '<CompleteMultipartUpload>
    <Part><PartNumber>1</PartNumber><ETag>"abc1"</ETag></Part>
    <Part><PartNumber>2</PartNumber><ETag>"abc2"</ETag></Part>
    <Part><PartNumber>3</PartNumber><ETag>"abc3"</ETag></Part>
</CompleteMultipartUpload>'

4. Or abort

curl -X DELETE "http://localhost:9000/media/big-video.mp4?uploadId=up_a3f8c01..." \
  --aws-sigv4 "aws:amz:us-east-1:s3" \
  --user "minioadmin:minioadmin"

Parallel parts in Python

from concurrent.futures import ThreadPoolExecutor

resp = s3.create_multipart_upload(Bucket="media", Key="video.mp4")
upload_id = resp["UploadId"]

def upload_part(part_number, body):
    r = s3.upload_part(
        Bucket="media", Key="video.mp4",
        UploadId=upload_id, PartNumber=part_number, Body=body
    )
    return {"PartNumber": part_number, "ETag": r["ETag"]}

with open("video.mp4", "rb") as f:
    parts_data = [(i+1, f.read(16*1024*1024)) for i in range(10)]

with ThreadPoolExecutor(max_workers=8) as ex:
    parts = list(ex.map(lambda p: upload_part(*p), parts_data))

s3.complete_multipart_upload(
    Bucket="media", Key="video.mp4",
    UploadId=upload_id, MultipartUpload={"Parts": parts}
)

List in-progress uploads

aws --endpoint-url http://localhost:9000 s3api list-multipart-uploads --bucket media
Auto-cleanup: abandoned multipart uploads (started but never completed or aborted) are removed 24 hours later. No manual janitor needed.
