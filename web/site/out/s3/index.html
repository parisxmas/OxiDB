S3

S3-compatible API

OxiDB ships an S3 HTTP server that speaks the AWS S3 protocol — AWS Signature V4 auth, multipart upload, presigned URLs, server-side encryption (SSE-S3 + SSE-C), object tagging, batch delete, range/conditional reads. It's a drop-in for aws-cli, boto3, mc (MinIO client), AWS SDKs, and anything else that talks S3.

One binary, two protocols. The same oxidb-server serves OxiDB's native protocol on port 4444 AND the S3 API on port 9000. Pick what you need with env vars. No extra processes.

What's supported

  • Bucket ops: create, list, delete, head, list-objects (with prefix & pagination)
  • Object ops: PUT, GET (with Range, conditional If-Match / If-None-Match), HEAD, DELETE, COPY (x-amz-copy-source)
  • Multipart upload: initiate, upload-part, complete, abort, list-parts; up to 10,000 parts and 5 GiB total
  • Auth: AWS Signature V4 (header), presigned URL, single-key or multi-tenant access keys
  • Encryption: SSE-S3 (server-managed AES-256-GCM), SSE-C (client-supplied key), default-bucket-encryption mode
  • Tagging: GET / PUT / DELETE on ?tagging, used for lifecycle and access policies
  • Batch delete: POST ?delete with up to 1000 keys at a time
  • CORS: configurable origin via env var

Where to start

Quick Start

Enable the S3 port, set credentials, upload your first object with aws-cli in under two minutes.

Auth

Single-tenant, multi-tenant, presigned URLs, what gets verified on every request.

Object operations

PUT / GET / HEAD / DELETE, range & conditional reads, copy, tagging.

Multipart upload

Stream multi-gigabyte objects in 5 MiB+ parts with parallel uploads.

Encryption

SSE-S3 with a server-managed key, or SSE-C with per-request keys.

Clients

aws-cli, boto3, mc/MinIO client, AWS SDK for JS — all confirmed working.

The 30-second smoke test

# 1. Start the server with S3 enabled
OXIDB_S3_PORT=9000 \
OXIDB_S3_ACCESS_KEY=minioadmin \
OXIDB_S3_SECRET_KEY=minioadmin \
OXIDB_DATA=./data \
oxidb-server &

# 2. Configure aws-cli
aws configure set aws_access_key_id minioadmin
aws configure set aws_secret_access_key minioadmin

# 3. Use it
aws --endpoint-url http://localhost:9000 s3 mb s3://photos
aws --endpoint-url http://localhost:9000 s3 cp ~/avatar.jpg s3://photos/me.jpg
aws --endpoint-url http://localhost:9000 s3 ls s3://photos/
