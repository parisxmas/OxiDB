    <h2><svg class="section-icon" width="22" height="22" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><polyline points="22 12 18 12 15 21 9 3 6 12 2 12"/></svg> Time-Series Engine</h2>
    <p class="section-desc">A standalone InfluxDB-style time-series engine, mounted like the SQL engine in the same process. Each series (measurement &times; tag-set &times; field) is a Gorilla-compressed columnar stream &mdash; about 0.3 bytes per point on regular data. Off by default; zero cost when unused.</p>

    <h3>Enable it</h3>
    <pre><code class="lang-bash">OXIDB_TSDB=1 ./oxidb-server
<span class="co"># data under &lt;OXIDB_DATA&gt;/tsdb (override with OXIDB_TSDB_DATA)</span></code></pre>

    <h3>Write points</h3>
    <p>TSDB requests carry <code>"engine": "tsdb"</code>, <code>"cmd": "tsdb"</code>, and an <code>"op"</code>. Fields are typed (float / integer / boolean / string).</p>
    <pre><code class="lang-json">{ "engine": "tsdb", "cmd": "tsdb", "op": "write",
  "measurement": "cpu", "tags": {"host": "a", "region": "eu"},
  "fields": {"usage": 0.63}, "ts": 1700000000000 }</code></pre>

    <h3>InfluxDB line protocol</h3>
    <p>Ingest the InfluxDB line protocol verbatim &mdash; ms timestamps, <code>now()</code> when absent.</p>
    <pre><code class="lang-json">{ "engine": "tsdb", "cmd": "tsdb", "op": "write_lp",
  "lp": "cpu,host=a,region=eu usage=0.63 1700000000000\ncpu,host=b usage=0.41" }</code></pre>

    <h3>Query &amp; downsample</h3>
    <p>Filter by measurement, field, tags, and a <code>[start, end)</code> window; optionally downsample with <code>GROUP BY time(interval)</code> and group by tags.</p>
    <pre><code class="lang-json">{ "engine": "tsdb", "cmd": "tsdb", "op": "query",
  "measurement": "cpu", "field": "usage",
  "tag_filters": [{"key": "host", "value": "a"}],
  "start": 1700000000000, "end": 1700003600000,
  "interval": 600000, "group_by": ["region"],
  "agg": "mean" }</code></pre>
    <h3>Aggregations</h3>
    <div class="table-wrap">
      <table>
        <thead><tr><th>Agg</th><th>Meaning</th></tr></thead>
        <tbody>
          <tr><td><code>mean sum min max count first last distinct</code></td><td>Standard numeric aggregations</td></tr>
          <tr><td><code>rate</code></td><td>Per-second change (for counters)</td></tr>
          <tr><td><code>percentile</code> (+ <code>p</code>), or <code>p95</code> shorthand</td><td>Linear-interpolated percentile</td></tr>
        </tbody>
      </table>
    </div>
    <p>Text (string) fields support <code>first</code> / <code>last</code> / <code>count</code> / <code>distinct</code>.</p>

    <h3>Continuous-aggregate rollups</h3>
    <p>Materialize completed time buckets of every numeric series into a derived measurement (<code>&lt;m&gt;@&lt;label&gt;</code>). Incremental via a crash-safe per-series watermark &mdash; no double-count on restart.</p>
    <pre><code class="lang-json">{ "engine": "tsdb", "cmd": "tsdb", "op": "rollup_add",
  "measurement": "cpu", "interval": 60000, "aggs": ["mean", "max"] }
{ "engine": "tsdb", "cmd": "tsdb", "op": "rollup_refresh", "now": 1700003600000 }
<span class="co">// query the rollup as measurement "cpu@1m", field "usage_mean"</span></code></pre>

    <h3>Retention &amp; checkpoints</h3>
    <p>Retention drops whole expired blocks &mdash; durable for free. A checkpoint seals buffers, writes a fresh snapshot, and rotates the WAL (auto past 8&nbsp;MiB).</p>
    <pre><code class="lang-json">{ "engine": "tsdb", "cmd": "tsdb", "op": "retention", "cutoff": 1699000000000 }
{ "engine": "tsdb", "cmd": "tsdb", "op": "checkpoint" }
{ "engine": "tsdb", "cmd": "tsdb", "op": "stats" }</code></pre>

    <h3>Backup &amp; restore</h3>
    <p>Like the SQL engine, the TSDB has a consistent <strong>low-lock online backup</strong> &mdash; it pins a committed generation and compresses with the write lock released, so ingestion keeps flowing. Admin-only.</p>
    <pre><code class="lang-json">{ "engine": "tsdb", "cmd": "backup",  "path": "/backups/tsdb.tar.gz" }
{ "engine": "tsdb", "cmd": "restore", "archive": "/backups/tsdb.tar.gz", "target": "/data/restored" }</code></pre>

    <h3>Persistence</h3>
    <p>A versioned block snapshot + per-generation WAL, with a MANIFEST as the atomic commit point. Every point is WAL-appended; a checkpoint writes a fresh snapshot, atomically replaces the MANIFEST, then rotates the WAL &mdash; a crash on either side never double-counts. Node-local. A Go client ships in the repo.</p>
